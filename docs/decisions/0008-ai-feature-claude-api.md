# 0008. AI-функція зрізу 4: Claude API (Haiku 5.5) замість OpenRouter `:free`

- Статус: прийнято (рішення власника репо 2026-11-14); замінює в ADR 0006 провайдера й модель
- Дата: 2026-11-14
- AC: AC-INTAKE-01, 02, 04, 06, 07, 08 (зріз 4, WS10)

## Контекст

ADR 0006 обрав безкоштовні моделі OpenRouter з ланцюжком fallback. Власник репо вирішив використати Claude API: ключ
Anthropic уже є, а безкоштовні моделі не дають стабільного eval (зникають, ліміт 50 запитів на добу на акаунт).

Відомий конфлікт з README домашки HW10: там сказано, що платна модель у ланцюжку «не зараховується» (трек B, ключ
`OPENROUTER_API_KEY`, `:free`). Власник прийняв цей ризик свідомо; відхилення вказуємо в описі PR здачі.

## Рішення

- Залежність `@ai-sdk/anthropic@4.0.96` (точна версія) замість `@openrouter/ai-sdk-provider`. Саме ця версія залежить від
  тих самих `@ai-sdk/provider@4.0.35` і `@ai-sdk/provider-utils@5.0.74`, що й `ai@7.0.162`: новіші версії тягнуть власний
  `@ai-sdk/provider`, і `tsc` падає на несумісних типах потоку.
- Модель — `claude-haiku-5-5`, одна, без ланцюжка fallback (`src/lib/ai/models.ts`). Haiku — найдешевша, для витягування
  полів з короткого тексту вистачає: живий eval на GC-01…10 — 10/10 (`evals/reports/`).
- Ключ `ANTHROPIC_API_KEY` читає лише `src/lib/ai/anthropic.ts` з `import "server-only"`, без `NEXT_PUBLIC_`
  (`tests/ai-key.test.ts`). Той самий ключ локально — у `.env.local`, на проді — у Vercel лише Production (Preview без ключа показує «недоступний» і нічого не коштує).
- Ліміт запитів: 10 чернеток на годину на користувача (захист платного ключа від зловживання). Рахує база: таблиця
  `intake_draft_requests` без прямого доступу через Data API і функція `private.take_intake_draft_slot` (`security definer`,
  блокування по користувачу), обгортка `public.take_intake_draft_slot()` для `supabase.rpc`. Дія перевіряє ліміт після ролі
  й перед моделлю; помилка перевірки теж закриває. Вичерпаний ліміт — те саме «помічник недоступний» (AC-INTAKE-08).
  Число 10 — припущення розробника, PM може змінити.
- `temperature` не передаємо: Haiku 5.5 її не приймає. Стабільність дають схема zod і правила коду (`intake.ts`).
- 429 розпізнаємо за статусом відповіді (`statusCode === 429`); спеціальний випадок OpenRouter «429 у тілі HTTP 200»
  прибрано разом із провайдером.
- Скрипти `ai:models` і `ai:quota` (публічний список і лічильник безкоштовних моделей OpenRouter) видалено: для Claude API
  вони не мають змісту. Живий eval не перевіряє денний залишок.
- Без змін із ADR 0006: AI SDK 7 (`generateText` + `Output.object`), схема zod зі станами, правила чернетки в коді, людина
  в контурі, golden cases PM, офлайн-реплей у `npm test`, живий `npm run eval` вручну.

## Розглянуті варіанти

- Лишити OpenRouter `:free` — відповідає README курсу й безкоштовний, але ліміт 50 запитів на добу спільний для eval,
  UAT і приймання PM, а моделі можуть зникнути.
- Ланцюжок Claude → безкоштовна модель — ні: ускладнює eval і повертає порушення README без користі.
- `claude-sonnet-5-5` / `claude-fable-5-2` — ні: дорожчі, а Haiku проходить усі golden cases.

## Наслідки

- Простіше: немає денного ліміту безкоштовних моделей, eval відтворюваний, 429 майже не буває.
- Складніше: виклики платні, тому: роль перевіряється до виклику (Р31), ліміт 10 на годину на користувача і загальна стеля 200 запитів на добу (міграція `intake_draft_daily_cap`, фідбек лектора WS10), `maxRetries` ≤ 1,
  текст ≤ 2000 символів; ліміт витрат на ключ власник задає в консолі Anthropic. Ключ у Vercel — лише Production (Preview не
  витрачає гроші на кожен PR).
- Приватність: Claude API за замовчуванням не використовує вхідні дані для навчання, але дані в промпті, golden cases і
  eval лишаються лише синтетичними (`*@example.test`); у формі підказка не вставляти діагнози.
- Записи `tests/fixtures/golden/recorded.json` оновлюємо (`RECORD=1 npm run eval`), коли змінюється модель, промпт
  (`DRAFT_PROMPT_VERSION`) або схема.
