# 0006. AI-функція зрізу 4: AI SDK + OpenRouter (безкоштовні моделі) + zod

- Статус: прийнято (залежності набору курсу погодив власник 2026-11-14)
- Дата: 2026-11-14
- AC: AC-INTAKE-01, 02, 03, 04, 05, 06, 07, 08, 09 (зріз 4, WS10)

Джерело файлів: набір курсу `materials/ai-feature` (koldovsky/2026-quitcode-10-ai-features-hw), адаптований під цю функцію.

## Контекст

Зріз 4 додає AI-функцію: планувальник вставляє вільний текст звернення клієнта, застосунок заповнює форму нової картки
чернеткою, а картку створює лише людина (`requirements/36-planuvalnyk-otrymuie-chernetku-kartky.md`). Обмеження:

- Next.js 16.4 на Vercel Hobby. Функція викликає модель один раз; агентний цикл не потрібен.
- Модель — безкоштовна через OpenRouter, ключ власний. Ліміт безкоштовних моделей — 20 запитів/хв і 50/день на акаунт;
  додаткові ключі його не збільшують. Безкоштовні моделі з'являються й зникають.
- Безкоштовні ендпоінти можуть зберігати запити й навчатися на них: у промпт, golden cases і eval — лише синтетичні дані;
  у формі підказка не вставляти діагнози й інші дані про здоров'я.
- Відповідь моделі недетермінована, а CI має бути без мережі й без секретів.

## Рішення

- Нові залежності (точні версії): `ai@7.0.162`, `@openrouter/ai-sdk-provider@3.1.0`, `zod@4.6.7`, `server-only@0.0.1`.
- Виклик — `generateText` + `Output.object({ schema })` (AI SDK 7). Схема zod (`src/lib/ai/schema.ts`) має стан
  `status: ok | needs_info | refused`; «невідоме» — `null`. Значення полів у схемі вільні рядки: що з них потрапляє у форму
  (дата не з майбутнього, тип за віком, формат email, мова з двох), вирішує код (`src/lib/ai/intake.ts`), а не промпт.
- `askModel(text, today, model)` (`src/lib/ai/draft.ts`) — чиста функція, модель передають параметром. Ключ
  `OPENROUTER_API_KEY` читає лише `src/lib/ai/openrouter.ts` з `import "server-only"`; без `NEXT_PUBLIC_` (перевіряє
  `tests/ai-key.test.ts`).
- Ланцюжок моделей, лише `:free`: `google/gemma-4-31b-it:free` → `google/gemma-4-26b-a4b-it:free` →
  `nvidia/nemotron-3.5-super-vl:free`. Файлів функція не приймає, тож плагін обробки PDF не підключаємо.
- Людина в контурі: Server Action лише повертає чернетку у форму; запис робить наявна `createClientCard` з правилами й RLS
  бази (ADR 0004). Дія чернетки не торкається таблиць і перевіряє роль до виклику моделі.
- Перевірка якості: 10 golden cases PM у `tests/fixtures/golden/cases.json`. LLM-суддю з набору не беремо: очікуване —
  точні поля й дослівні повідомлення, оцінка детермінована. Офлайн-реплей записаних відповідей — у `npm test`; живий
  прогін `npm run eval` вручну зі звітом у `evals/reports/`.

## Розглянуті варіанти

- Claude Agent SDK у функції Vercel — ні: запускає підпроцес Claude Code (~320–342 МБ), пакет функції Vercel Hobby — до
  250 МБ; потрібен один виклик моделі, а не агентний цикл.
- Пакет `openai` з `baseURL` OpenRouter або `@openrouter/sdk` — ні: немає валідації схемою з типізованими помилками й
  тестових моделей (`MockLanguageModelV4`) в одному API.
- `openrouter/free` (випадкова безкоштовна модель) — ні: результат golden cases не відтворюється.
- Платний ключ — ні: курс використовує безкоштовні моделі; перехід на платного провайдера — заміна однієї фабрики в
  `src/lib/ai/models.ts`.
- Мінімум залежностей (лише `zod` і `server-only`, виклик через `fetch`) — ні: власну обгортку, розбір відповіді й
  mock-моделі довелося б писати й перевіряти самим за обмеженого часу.

## Наслідки

- Простіше: провайдера й модель міняємо в одному файлі; CI не залежить від мережі й ліміту; правила чернетки перевіряє код.
- Складніше: безкоштовна модель може зникнути або впертися в ліміт — інтерфейс показує повідомлення AC-INTAKE-08, а
  людина заповнює форму вручну. Ланцюжок перевіряємо `npm run ai:models` перед роботою.
- Записи `tests/fixtures/golden/recorded.json` оновлюємо (`RECORD=1 npm run eval`), коли змінюється промпт
  (`DRAFT_PROMPT_VERSION`) або схема.
