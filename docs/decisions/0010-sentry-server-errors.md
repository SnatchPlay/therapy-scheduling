# 0010. Sentry для серверних помилок, без збору даних клієнтів

- Статус: запропоновано
- Дата: 2026-11-22
- AC: — (операційне рішення, поведінка для користувача не змінюється)

## Контекст

WS11 вимагає трекер помилок сервера. Без нього збій у server action чи на сторінці видно лише в Runtime Logs Vercel, які на
Hobby живуть 1 годину, не групують однакові помилки й нікому не сигналізують. У запитах застосунку — дані клієнтів практики
психотерапії (ім'я, email, дата народження, текст звернення), тож трекер не має їх збирати.

Sentry SDK 11 за замовчуванням збирає більше, ніж 10: cookie, заголовки, тіла запитів, дані користувача, текст SQL, вхід і вихід
AI SDK, змінні в кадрах стеку (`dataCollection`; `sendDefaultPii` прибрано). Це перевірено за встановленим кодом
`@sentry/core` 11.12.0, а не за пам'яттю.

## Рішення

- `@sentry/nextjs` 11.12.0 (точна версія, як решта залежностей). Sentry SaaS, організація `quitcode-lj`, проєкт
  `javascript-nextjs` (`next.config.ts`).
- Лише сервер: `Sentry.init` у `src/instrumentation.ts`, `onRequestError = Sentry.captureRequestError`. Клієнтської частини,
  `global-error.tsx`, edge-конфігу, Session Replay, трасування й тунелю `/monitoring` немає: помилки браузера ніхто не читає,
  а запис екранів працівників з даними клієнтів неприпустимий.
- Збір даних вимкнено повністю: `userInfo`, `cookies`, `httpHeaders`, `urlQueryParams`, `httpBodies: []`, `genAI`, `mcp`,
  `databaseQueryData`, `queues`, `stackFrameVariables`. Тест `src/instrumentation.test.ts` падає, якщо хоч один прапор змінено.
- Інтеграцію `Console` вимкнено: інакше кожен `console.*` (зокрема помилки з повідомленням бази, які пише Next) стає крихтою з
  текстом, а `beforeSend` крихт не чистить.
- `beforeSend` ховає вміст лапок у тексті винятку: помилка типу в Postgres повторює введене значення
  (`invalid input syntax for type uuid: "…"`).
- DSN — змінна `SENTRY_DSN` (не в коді): без неї Sentry вимкнений (локально, CI). Середовище події — `appEnv()` (`APP_ENV`,
  на staging `staging`), інакше `VERCEL_ENV`. `SENTRY_AUTH_TOKEN` (вивантаження source maps) — лише у Vercel й у локальному
  `.env.sentry-build-plugin` (у `.gitignore`), ніколи в GitHub чи git. `SENTRY_TRACES_SAMPLE_RATE` і `SENTRY_TRACE_LIFECYCLE`
  не задавати: SDK читає їх із середовища й увімкнув би трасування з URL.
- Правило для коду: у Sentry не відправляємо вільний текст (`captureMessage` з даними користувача, власні крихти). Події про
  AI-виклик — `llm.call` через `src/lib/log.ts` (список дозволених полів).
- `GET /api/sentry-test` — навмисна помилка лише для адміністратора (`requireRole("admin")`), доказ, що події доходять.
  Після доказу на staging маршрут прибрати окремим PR або записати в `docs/runbook.md` як постійний (рішення власника репо).

## Розглянуті варіанти

- Лише Runtime Logs Vercel — ні: 1 година зберігання, немає групування й сигналу.
- Sentry з налаштуваннями майстра (клієнт, Replay, трасування) — ні: типові налаштування v11 збирають дані клієнтів.
- Лишити типовий збір і чистити `beforeSend` — ні: список «небезпечного» ніколи не повний, список «потрібного» короткий
  (так само, як `src/lib/log.ts`).
- Інший трекер (власний хостинг) — ні: окрема інфраструктура для практики з однією людиною на черговості.

## Наслідки

- Простіше: помилку сервера видно зі шляхом і стеком, групування й середовище (`production` / `staging`) безкоштовно.
- Складніше: у події немає ні тіла запиту, ні користувача, ні значень змінних — розбір спирається на шлях, код помилки й
  `llm.call`. Оновлення SDK, що додасть нову категорію збору, тест `dataCollection` не помітить: після мажорного оновлення
  прочитати зміни `dataCollection`.
- Перевірено 2026-11-22 на staging за JSON справжньої події: `request` — лише метод, `user` — лише `geo` (регіон сервера
  Vercel), ні cookie, ні заголовків, ні тіл, ні змінних кадрів. Крихти — два HTTP-записи про запити до Supabase (JWKS і
  `/rest/v1/profiles`) без query-рядка в цій одній події: інтеграція `Console` вимкнена, HTTP-крихти лишаються. Те, що
  query-рядок вилучає саме `urlQueryParams: false`, у коді SDK не простежено; перед прийняттям ADR глянути ще одну подію з
  маршруту, де запит до Supabase має фільтр (`/clients`).
- Відома обмеженість: source maps вивантажуються (Sentry знаходить карту за debug ID), але кадри серверних чанків не
  розшифровуються (`js_invalid_sourcemap_location`). Індексована карта Turbopack має `offset.line = 1`, а в чанк плагін
  вставив два рядки з debug ID: позиція в карті зсунута на рядок (локально: у карті `throw` на рядку 23 → `route.ts:6:8`,
  у чанку — на рядку 25). Стек читається за текстом помилки й шляхом маршруту; не виправлено.
