# 0007. «Not set» не повернути: тригер замість `with check`; email-обмеження validated

- Статус: замінює 0005 (лише правило «Not set не повернути» і `with check` політики; решта 0005 чинна)
- Дата: 2026-11-14
- AC: AC-INS-02 (повернути «Not set» не можна), AC-INS-05 (терапевт не змінює статус)

## Контекст

Фідбек викладача до WS9. ADR 0005 виразив правило «„Not set“ — лише початковий» як `with check (insurance_status in
('Verified', 'Not accepted', 'Private pay'))` політики `clients_update_insurance_staff` і відкинув тригер. Два наслідки:

- будь-яка інша відмова на `update` для картки з початковим статусом приходила як `42501` від RLS: тест «інші колонки
  недоступні» на картці «Not set» лишався б зеленим навіть при `grant update` на всю таблицю;
- друга дозвільна політика на `update` (через OR) тихо дозволила б повернути «Not set».

Окремо `clients_email_check` лишався `not valid`: Postgres перевіряє такий check на кожному оновленому рядку, тож картка
зрізу 1 з email без крапки після «@» не дала б змінити жодну колонку. «На проді таких немає» було перевірено один раз
запитом (пункт 18.3 плану `impl-insurance-status` лишився «не виконано»).

## Рішення

Міграція `20261114153320_insurance_not_set_trigger_validate_email.sql`:

- `alter table public.clients validate constraint clients_email_check`: `db-deploy` перевіряє всі рядки проду й або
  проходить, або зупиняє застосування з помилкою (заміна одноразового запиту в SQL Editor).
- Тригер `clients_insurance_not_set` (`before update of insurance_status`, функція `private.forbid_insurance_not_set`,
  `security invoker`, `search_path = ''`): `new.insurance_status = 'Not set'` → `42501`, «permission denied: статус «Not
  set» не повернути». Працює однаково для всіх ролей, зокрема `service_role`; на оновлення інших колонок не реагує.
- Політика лишається однією; її `with check` — перевірка ролі (`private.is_scheduler_or_admin()`), як і `using`. Значення
  поза списком відхиляє `clients_insurance_status_check` (`23514`).

Тести: «інші колонки недоступні для update» працює на картці з виставленим статусом і перевіряє текст «permission denied for
table clients» (відмова колонкового права, не RLS); «Not set» перевіряється за текстом тригера. Мутанти I2 (тригер), I10
(право через роль-посередника) і I11 (`validate`) — `scripts/mutants.mjs`.

## Розглянуті варіанти

- Лишити `with check` (0005) — ні: див. Контекст.
- Друга політика на `update` — ні: політики складаються через OR і послабили б перевірку ролі.
- Функція `rpc` — ні: одна колонка, одне правило.

## Наслідки

- Повернути «Not set» не можна ніким, зокрема service_role-скриптом (раніше service_role міг): якщо колись знадобиться
  скинути статус, це окреме рішення й нова міграція.
- Наступна колонка картки, яку можна змінювати, — новий ADR (межа 0005 не змінилась).
