# 0003. Storybook для компонентів дизайн-системи

- Статус: прийнято
- Дата: 2026-10-25
- AC: — (інструмент розробки; поведінка застосунку не змінюється)

## Контекст

Дизайн-система (ADR 0002) живе в `DESIGN.md`, токенах і `src/components/ui`. Побачити всі варіанти компонента в обох темах,
не відкриваючи сторінки зрізу з даними й без входу, можна лише в окремому каталозі. Той самий каталог дає агенту й
рецензенту місце для візуальної перевірки (цикл «зняв → порівняв → виправив»), а axe в панелі — перевірку контрасту й
доступності кожного варіанта.

## Рішення

- Storybook 10.6.3 з `@storybook/nextjs-vite` (Vite-збірка, без окремого Webpack), додатки `@storybook/addon-a11y` і
  `@storybook/addon-docs`, `eslint-plugin-storybook`; усі версії точні. Конфіг — `.storybook/`; телеметрія вимкнена.
- Історії лежать поруч із компонентами (`src/**/*.stories.tsx`): Button, Input + Label, NativeSelect, Table, Alert,
  EmptyState, StatusBadge (усі п'ять статусів і невідомий).
- Токени — ті самі, що в застосунку: `.storybook/preview.ts` імпортує `src/app/globals.css`; Tailwind 4 у Vite дає
  `@tailwindcss/vite` (застосунок збирає Next через `@tailwindcss/turbopack`). Темна тема, як і в застосунку, — за системою.
- Шрифт Geist підключає `next/font` у застосунку; у Storybook лише системні запасні (`.storybook/preview-head.html`).
- Окремий workflow `.github/workflows/storybook.yml` збирає каталог на кожен PR; у ruleset він не обов'язковий.
- Правило в `AGENTS.md`: новий компонент у `src/components/ui` — разом з історією.

## Розглянуті варіанти

- Лишити лише сторінки зрізу — ні: варіанти компонентів (помилка поля, `Past`, `Unknown`) на сторінках не видно, а
  перевірка потребує входу й даних.
- Інший каталог (Ladle, Histoire) — ні: Storybook має додаток axe, підтримку Next і є знайомим стандартом; Ladle не має
  аналога перевірки доступності в панелі.
- Хмарний сервіс візуальних знімків (Chromatic) — ні: окремий акаунт і секрет, для навчального проєкту зайве; знімки
  знімаємо Playwright на зібраному каталозі.

## Наслідки

Нові devDependencies (`storybook`, `@storybook/nextjs-vite`, два додатки, `eslint-plugin-storybook`, `@tailwindcss/vite`) не
потрапляють у збірку застосунку; `npm audit --omit=dev` лишається 0. Зібраний каталог (`storybook-static`) у git не
йде й виключений з ESLint. Перемикача теми в каталозі немає: темну перевіряють системним налаштуванням чи емуляцією
`prefers-color-scheme`. Автотестів історій (`addon-vitest`) поки немає.

## Як перевіряємо

Job «Storybook: збірка» в `.github/workflows/storybook.yml` (червоний, якщо історія не збирається чи імпорт компонента
зламано), `npm run lint` (історії проходять `eslint-plugin-storybook`) і `npm run typecheck`. Доступність: axe
(WCAG A/AA) на всіх історіях у світлій і темній темі — без порушень на цьому коміті (результат у описі PR).
