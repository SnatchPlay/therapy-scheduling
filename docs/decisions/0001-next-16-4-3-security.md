# 0001. Next.js 16.4.0 → 16.4.3 (безпека)

- Статус: прийнято
- Дата: 2026-10-25
- AC: — (залежність, поведінка не змінюється)

## Контекст

`AGENTS.md` фіксує стек («Next.js 16.4», не оновлювати без ADR). Після закріплення `next` 16.4.0 вийшли поради з безпеки
(`npm audit --omit=dev`, critical, діапазон 16.0.0–16.4.0): віддалене виконання коду без автентифікації через оптимізатор
зображень із SVG (GHSA-2464-fhr4-w9xw) і через `use cache` з типізованими масивами (GHSA-673q-mjm6-r5xr), DoS у Server
Actions (GHSA-p3m5-59mp-jv5r). Виправлення — у 16.4.1. SVG-оптимізатор і `use cache` у проєкті не використовуються, Server
Actions — так (`/login`, `/clients`, `/slots`, `/holds`). `npm run build` після цього друкує попередження про вразливість.

## Рішення

`next` і `eslint-config-next` — точно 16.4.3 (як і раніше, без `^`): остання серія 16.4 із виправленням. 16.4.2 і 16.4.3 —
бекпорти (Turbopack, «не вантажити runtime app-page у `proxy.ts`», шрифти Google, OpenTelemetry), без нових можливостей.
Лінія 16.4 лишається: React 19.3, App Router, `src/`, без Cache Components. Перевірка: lint, typecheck, 195 тестів, build з
`ƒ Proxy (Middleware)`, `npm audit --omit=dev` — 0 вразливостей; після деплою — прод (`/login`, перенаправлення, вхід).

## Розглянуті варіанти

- Лишити 16.4.0 — ні: критична вразливість у залежності, що обслуговує публічні маршрути.
- Перейти на 16.5 (canary) чи «latest» — ні: `AGENTS.md` не радить, шаблон цього не перевіряв.
- Закріпити `^16.4.3` — ні: точні версії забезпечують однакову збірку в CI, Vercel і локально.

## Наслідки

Збірка й Vercel використовують 16.4.3; наступні патчі серії 16.4 — окремим малим PR з тим самим переліком перевірок.
`npm audit` для дерева розробки ще показує `zod` < 4.6.6 (high) через `@fission-ai/openspec` і
`eslint-plugin-react-hooks`: це інструменти розробки, у зібраний застосунок не потрапляє.
