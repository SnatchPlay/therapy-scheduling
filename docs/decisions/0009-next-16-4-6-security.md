# 0009. Next.js 16.4.3 → 16.4.6 (безпека)

- Статус: замінює 0001
- Дата: 2026-11-21
- AC: — (залежність, поведінка не змінюється)

## Контекст

`AGENTS.md` фіксує стек («Next.js 16.4», не оновлювати без ADR), ADR 0001 закріпив 16.4.3. Лектор WS10 у фідбеку вказав на дві
moderate-вразливості в 16.4.3, виправлені в 16.4.6 (остання версія лінії 16.4 на 2026-11-21: `npm view next@16.4.6 version`).

## Рішення

`next` і `eslint-config-next` — точно 16.4.6 (без `^`, як в ADR 0001). Лінія 16.4 лишається: React 19.3, App Router, `src/`,
без Cache Components; жодних змін коду застосунку. Перевірка: lint (0 warnings), typecheck, `npm test`, `npm run build` з
`ƒ Proxy (Middleware)`, `npm audit --omit=dev` — 0 вразливостей; після деплою — `/api/health` і прод-UAT.

## Розглянуті варіанти

- Лишити 16.4.3 — ні: відома вразливість у залежності, що обслуговує публічні маршрути.
- Перейти на 16.5 чи «latest» — ні: `AGENTS.md` лінію 16.4 фіксує, шаблон старшого не перевіряв.

## Наслідки

- Простіше: попередження про вразливість зникає, D0 (`next` ≥ 16.4.1) лишається виконаним.
- Складніше: бекпорти 16.4.4–16.4.6 перевірено лише набором тестів проєкту й збіркою; поведінку Server Actions і `proxy.ts`
  на проді підтверджує UAT після деплою.
