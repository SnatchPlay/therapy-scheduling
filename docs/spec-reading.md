## Власні припущення

- «Вільний слот» — слот без активного утримання й без підтвердженого сеансу; прострочене утримання слот не займає
  (глосарій «Прострочене утримання»: «Його слот знову вільний»).
- Статус утримання («Held» / «Expired» / «Confirmed») рахуємо в момент перегляду від часу створення, без фонової
  задачі («Що поза scope»: «утримання звільняється за часом його створення, а не фоновою задачею»).
- «Одночасно» в AC-HOLD-04 перевіряємо двома паралельними спробами утримати слот: базу захищає правило «не більше
  одного активного утримання чи сеансу на слот» з припущень PM.
- Після прострочення слот можна утримати знову за будь-яким клієнтом, зокрема тим самим (AC-HOLD-06; відповідь PM у
  Sofiia-pm/therapy-scheduling-spec#5: планувальник може «утримати слот знову»).
- Порожнє ім'я — зокрема ім'я лише з пробілів; «valid email» з AC-HOLD-11/15 перевіряємо як «один знак @ з текстом
  до й після, без пробілів».
- Терапевти, їхні слоти й клієнти для демо — синтетичні початкові дані (`*@example.test`).
