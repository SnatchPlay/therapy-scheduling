# Ретро WS9: що б ми взяли з фабрики у свій звичайний процес

Зріз 3 (статус перевірки страхування) зроблено звичайним способом, без двійника й фабрики. Нижче — станції фабрики й що з ними у цьому репо. «Візьмемо» — це план, а не зроблене: файли, які він змінить, названо.

- **Допуск (задачу без червоного тесту не беремо).** Частково є: `spec-review`, `openspec validate --strict` і `npm run ac:coverage` ловлять AC без сценарію чи тесту, але не вимагають тесту ДО коду. **Візьмемо:** у `openspec/config.yaml`, `rules.tasks`, — кожна задача починається з пункту «червоний тест від AC». У зрізі 3 побічний ефект на старі картки (`clients_complete_check` перевіряє й `update`, рішення Р27) знайшов лише тест, написаний після коду.
- **Захищені тести (виконавець не чіпає тести).** Не було: код і тести я писав в одній сесії. **Візьмемо:** для кожного відмовного AC тест пише окрема сесія лише з тексту AC. Для зрізу 3 так зроблено: `tests/db/insurance-status-blind.test.ts`, 13 тестів. Крок запишемо в `docs/reference/validation.md`, розділ «Перед PR гілки». Заборону `Edit(tests/**)` у `.claude/settings.json` не беремо: вона ламає звичайну роботу.
- **Приховані сценарії.** Не потрібно, бо сліпі тести окремої сесії й рецензент UAT «наосліп» (`scripts/uat/review.mjs`) дають те саме, що прихований набір, а шифрований набір має сенс лише для автономного виконавця. Сліпі тести самі вбили 4 з 8 SQL-мутантів (усе, що випливає з тексту AC); решту 4 — правила поза текстом AC — вбили наші тести.
- **Мутації.** Уже є: `scripts/mutants.mjs` (`npm run mutation:sql`) і `.quality-trial/stryker.sh`; у зрізі 3 вбито 8 з 8 SQL- і 9 з 9 TypeScript-мутантів. **Візьмемо:** у `.quality-trial/stryker.sh` виключити `tests/scripts/check-action-auth.test.ts` з початкового прогону: Stryker не вміє мутувати server actions, бо його службовий виклик у тілі функції ламає правило `check:actions` (довелося замінити точковими мутантами T4–T8).
- **Повтор (однакові результати двічі).** Немає. **Візьмемо:** `--repeat-each 2` у кроці Playwright файла `.github/workflows/e2e.yml`. Негативний контроль NC-2 на проді впав на таймауті хука `afterEach`, а не на вердикті, і без повтору не відрізнити флейк від вади.
- **Рев'ю-спростування (інша модель шукає, що зміна не працює).** Для UAT є: Haiku → Sonnet у `scripts/uat/review.mjs` знайшов у зрізі 3 три слабкі докази мого сценарію, яких я не бачив (кадр без банера, «Private pay» замість «Not accepted» у двох AC). Для коду лише `self-review` і `ponytail-review` тієї самої моделі; CodeRabbit власник вирішив не викликати. **Візьмемо:** крок «рев'ю коду іншою моделлю» в `docs/reference/validation.md`, «Перед PR гілки».
- **Пакет доказів з «Не перевірено».** Уже є: `docs/qa/proof-pack.md`. **Візьмемо:** заповнювати «Не перевірено» по ходу, у кожному PR, а не наприкінці: поле «Не перевірено» в `.github/pull_request_template.md`. У зрізі 3 такі пункти (відео не прикріплено, перший прогін UAT не збережено, AC-CARD-05 для PM) спливали лише в кінці.
- **Рівні автономії (автозлиття після воріт).** Не потрібно, бо `solo-main` уже вимагає PR і зелені `spec`, `app`, `conformance`, `db-check`, «Ворота: fallow audit», «Покриття: доменна підлога». Автозлиття міграції на прод без людини не беремо: міграція зрізу 3 мала ефект на старі картки, помітний лише з тесту й коментаря в `known-debt.md`.
- **Бюджети.** Частково: вартість рецензента UAT є у звіті ($0.0534 за прогін). **Візьмемо:** у `docs/qa/proof-pack.md` розділ «Вартість» з рядками «дата · крок · хв · $». У зрізі 3 ліміт моделі вичерпався посеред NC-прогону (рецензент «БЕЗ ВЕРДИКТУ») і не було видно, скільки коштував кожен крок.
